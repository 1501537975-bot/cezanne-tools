## 二、★★★ 关键结论（决定了方案走向）

### 结论 1：不能直接刷 K40G 的任何镜像

| | cezanne（你的机器） | K40G（移植包） |
|---|---|---|
| SoC | **MT6889**（天玑1000+） | **MT6893** |
| 设备树 model | `CEZANNE` | `ARES` |
| 屏幕 | `j10_38_08_0a_dsc_cmd,lcm` | K40G 自有 |
| 指纹 | `goodix,gt9896` | `gt9886` / `gt9896s` |
| 充电 | `ti,bq2597x-standalone` | K40G 自有 |
| 音频 | `fsa4480-audioswitch` | `et7480-audioswitch` |

→ **dtbo.img / vendor 绝不能用移植包的**。刷错 = 屏幕黑、指纹不认、充电不进、相机全废。

### 结论 2：我们要的是「能加载原厂 vendor 的内核」，不是移植包的内核

移植包的 4.14 Oblivion 内核：
```
Linux version 4.14.186-Oblivion-V4.0-DEV-ColorOS
CONFIG_LOCALVERSION="-Oblivion-V4.0-DEV-ColorOS"
```
→ vermagic 与原厂 `.ko` 不匹配 → **加载不了原厂 vendor 的 10 个 .ko**

但移植包的 vendor 是 MT6893 的，也不能用。**死结 → 必须自编内核。**

### 结论 3：Oblivion 内核证明我们的技术路线是对的

从移植包内核里解出的完整 config（5654 行），逐条印证我们 `build.sh` 的目标：

| 我们的 build.sh | Oblivion 实际 |
|---|---|
| `CONFIG_MODVERSIONS=y` | ✓ 一致 |
| `CONFIG_BPF_SYSCALL` | ✓ 一致 |
| `CONFIG_CGROUP_BPF` | ✓ 一致 |
| `CONFIG_NET_CLS_BPF` | ✓ 一致 |
| `CONFIG_EROFS_FS` + `_XATTR` | ✓ 一致（还多了 `_ZIP`） |
| `CONFIG_FHANDLE` / `INDIRECT_FD` | ⚠️ 我们比它多开了（对我们有利） |

**且它证明了 A16 与 A17 的分界**：
- A16 → 4.14 + BPF/EROFS 即可
- A17 → 需要 4.19（`NET_ACT_BPF` + `BPF_LSM`），4.14 跑不了

## 五、已解决的疑难（踩坑记录）

### 第 28 轮失败：版本串翻倍
```
kernel-release = 4.14.186-perf-00252-g2f26b5917fd6-perf-00252-g2f26b5917fd6
```
**根因**：`setlocalversion` 第 96 行
```sh
res="${res}${CONFIG_LOCALVERSION}${LOCALVERSION}"
```
两个渠道**相加**不是二选一。build.sh 同时喂了两份同值。
**修法**：`CONFIG_LOCALVERSION=""` + 只走 make 命令行 `LOCALVERSION=`。

### 第 29 轮失败：静默退出（无任何报错）
**根因**：`set -euo pipefail` 下 `grep` 无匹配返回 1 → **杀掉整个脚本**
```bash
val=$(grep -E "^${opt}=" .config | head -1 | cut -d= -f2)   # 无匹配 → 退出
[ -z "$val" ] && val="n"                                    # val 非空 → 退出
```
**修法**：全部改 if/else + 加 `scan_sete.py` 扫描器 + CI lint 关卡。

### 网络：git push 失败
DNS 把 `github.com` 解析到 fake-IP `198.18.0.7`。
```bash
export GIT_CONFIG_COUNT=1
export GIT_CONFIG_KEY_0=http.curloptResolve
export GIT_CONFIG_VALUE_0=github.com:443:140.82.112.3
git push origin main
```
