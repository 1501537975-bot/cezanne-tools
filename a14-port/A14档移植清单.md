# cezanne A14 档移植清单

> 红米 K30 至尊纪念版（cezanne / M2006J10C / MT6889 / 天玑1000+）
> 内核 4.14.186 · VNDK 31 · A-only · system-as-root · 无 EROFS
> 生成日期：2026-11-07 · 仅调研，未下载任何文件，未触碰手机

---

## 0. 结论速览

**只有 A14 档资源时，可成功移植的最高 Android 版本 = Android 14 (API 34)。**

依据（XDA 移植教程 "Fix BPF Issues" 原表）：

| Android | 最低内核 | 4.14 本机 | 绕法 |
|---|---|---|---|
| **14** | **4.14** | **刚好及格** | **换 com.android.tethering.apex 即可** |
| 15 | 4.19 | 超出 | 须 patch 内核 |
| 16 | 5.4 | 差两档 | 须 fake uname + BPF backport |
| 13 | 4.9 | 余量充足 | 无 BPF 门槛 |

**重要提醒：手机现在已经在跑 Android 16**（crDroid 12.12，2026-11-05 刷入成功）。
A16 能跑不是因为内核到 5.4，而是 **crDroid 12.12 这个 GSI 自带 "Universal legacy-kernel BPF fallback"**（系统侧绕法）。
官方 ColorOS / OriginOS / OneUI 移植包**不带**这个 fallback → 在 4.14 内核上会撞 BPF 墙。
**所以真正的判断标准不是 Android 版本号，而是「该 ROM 是否自带 legacy-kernel BPF 兼容」。**

| `TFSS/a13/` `a12/` `a12.1/` `a15/` `a16/` `a17/` | 其他版本备用 |
| `apex/` | APEX 文件库 |

> 教程原文提到 TFSS 在 "Defnotegor projects" SourceForge —— **已确认就是 `origin-oem-ports`**（项目现名 Theegoiko Projects），选对应 Android 版本目录即可。
> ⚠️ 教程整篇是 **Linux/WSL** 流程（`sudo bash run.sh`），Windows 上需 WSL2 或改用 Docker。

### apex 取用规则（A14 档）

| Android 版本 | 需要下的 apex |
|---|---|
| **A14（本次）** | **除 `com.android.vndk.v34.apex` 外的全部** |
| A15+ | 全部 |
| A13 | 仅 vndk v32 / v31 / v30 |
| A12.1 | vndk v31 / v30 |
| A12 | 仅 vndk v30 |

放置位置：`system_ext/apex/`（目录不存在就新建），**替换**而非追加同名文件。

### 打包格式铁律

- **4.19+ 内核 → EROFS**
- **4.14 本机 → 必须 ext4**（本机 `/proc/filesystems` 无 erofs，用 EROFS 必然卡开机）

## 3. 移植操作步骤（10 步，缺一步就开不了机）

### 准备

- [ ] 底包 MIUI V12.5.11.0.RJNCNXM（约 4.76GB，bigota 需 UA+Referer 且限速 20KB/s）
- [ ] platform-tools 34.0.4
- [ ] 目标包（A14 档，三选一）
- [ ] MIO Kitchen + UKL + TFSS/a14 + apex + init.gsi.rc

### Step 1 · 解包底包
MIO Kitchen 打开 MIUI V12.5.11.0 fastboot 包 → 解出 `vendor`、`odm`、`system_dlkm`、`vendor_dlkm`（**设备专属分区**）。
`system`、`product`、`system_ext`、`mi_ext` **不用**，这些从移植包里取。

### Step 2 · 解包移植 ROM
UKL `sudo bash run.sh` → 选 "super"（若有多个选项时 always super）→ 解出移植包的 system/product/system_ext。
> 若移植包是 `_a`/`_b` 双分区而底包不是 → **把 `_b` 合并进 `_a`**。

### Step 3 · 替换开机三件套 ★必做
在移植包的 `UnpackerSystem/system`（或 `system_a/system`）目录里，用 TFSS/a14 的文件替换：

- `bin/init`
- `lib64/libfs_mgr.so`
- `lib64/libfs_mgr.binder.so`

> 也可以用「同 Android 版本、能正常开机的 GSI」里的这三个文件代替 TFSS。
> **不做这步 → 卡一重启 / 直接进 Fastboot。**

### Step 4 · 换 SELinux mapping ★必做
把 **底包** 的 `/etc/selinux/mapping` 目录复制到移植包的 `system`、`product`、`system_ext` 三处。
> 移植包自带的老 mapping 与 4.14 内核不匹配 → 报错重启。

### Step 5 · 补 APEX
按上表把 A14 档 apex 全部放进 `system_ext/apex/`，**替换**同名文件。
> 不补 → 卡一或卡一重启（尤其 A13/14 补齐 vndk 版本不匹配时）。

### Step 6 · BPF 处理 ★A14 档核心
BPF 出问题的表现：**第一屏卡顿 20 秒后重启**，或 **第二屏 data 只加载 200MB 以内**。

**A14 + 4.14 的官方绕法：替换 `com.android.tethering.apex`**（用 A14 版本的新版 apex）。
> A14 最低 4.14，本机刚好卡线，所以**不用 patch 内核**，换 apex 即可。
> 橘子系统（ColorOS）若仍崩，额外替换该系统专属的 libbpf 文件。

### Step 7 · 改 build.prop
**删除这一行**（存在才删）：
```
media.settings.xml=/vendor/etc/media_profiles_vendor.xml
```
**加入这一组**：
```
ro.cp_system_other_odex=0
ro.nnapi.extensions.deny_on_product=true
ro.crypto.metadata_init_delete_all_keys.enabled=false
persist.sys.disable_rescue=true
ro.control_privapp_permissions=disable
persist.sys.usb.config=mtp,adb
ro.adb.secure=0
ro.secure=0
ro.debuggable=1
persist.service.adb.enable=1
```
**再检查 `system/apex`**：是**文件** → 加 `ro.apex.updatable=true`；是**文件夹** → 加 `ro.apex.updatable=false`。

### Step 8 · 修 vendor
在底包的 vendor（vendor_a）目录里：
1. **删除 `overlay` 整个目录**
2. 把 `etc/group`、`etc/passwd` 换成**移植包**里解出来的版本

### Step 9 · permissive（强烈建议）
在 `system/init/hw/init.rc` 加：
```
setprop init.svc.selinux_audit permissive
```
> XperiaUI 是强制项，其他强烈建议。**permissive 有安全风险，仅用于移植测试，别当日常系统。**

### Step 10 · init.gsi.rc + 打包
把 `init.gsi.rc` 放进 `system_ext/etc/init/`。

**打包：UKL 选 ext4**（4.14 内核只能用 ext4）。

### 各 ROM 专属补充

**MIUI / 澎湃OS**
- 国区包 → `system/system/build.prop` 加 `ro.miui.region=cn`（**防重启**）
- 删掉 `product_build.prop` 里所有 Dolby 相关行
- 内核 4.4/4.9 才需换 surfaceflinger.so（本机 4.14 不需要）

**ColorOS**
- 底包 passwd/group 替换（Step 8 已做）
- 卡二多为 SELinux 报错 / BPF 不兼容 / 底层 HAL 缺失
- 屏幕 SF 报错 → 删 Product 分区多余配置
- 补 `init.gsi.rc`（解决橘子系统与老底包卡二）
- 补 `system_ext/priv-app/com.qualcomm.location` 删除（高通定位冲突，MTK 一般不涉及）

**OriginOS**
- 安卓12老内核基本无法适配新版系统
- 安卓13/14 → 需替换**专属 Tethering 模块**
- OriginOS 5 → 必须删除/关闭 **Tango 服务**（A14 档的 OriginOS 4 不涉及）

## 4. 刷入流程（fastbootd 直刷 system，可逆）

沿用 11-05 已验证成功的流程，**不刷 flash_all**（不重写 preloader/lk，风险低、可逆）：

```bash
adb reboot bootloader
fastboot reboot fastboot          # 进 fastbootd
fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img
fastboot --disable-verity --disable-verification flash vbmeta_system vbmeta_system.img
fastboot --disable-verity --disable-verification flash vbmeta_vendor vbmeta_vendor.img
fastboot erase product
fastboot erase system_ext         # 本机无此逻辑分区会报 "Partition doesn't exist"，跳过
fastboot erase system
fastboot flash system system.img  # 稀疏镜像，约 110 秒
fastboot erase userdata           # Windows 下 fastboot -w 会失败，用 erase 代替
fastboot erase metadata
fastboot reboot
```

> A14 档不需要降底包（11-05 已证实当前 vendor 上直接刷 GSI 可行）。
> 若走设备树级路线（Recovery 卡刷），需先刷 MIUI V12.5.11.0 底包 → 四清 + 格式化 data → 卡刷 ROM → 刷 root。

## 5. 验证顺序（从快到慢，失败立刻回滚）

**第 1 步 · 最快验证（30 分钟，零改包）**
先直接刷 **A14 档现成 GSI**（如 `Coloros-ossi-14-…`），不动任何文件。
- 开机成功 → 说明 A14 档在这台机器上可行，再决定要不要做深度移植
- 卡 BPF（20 秒重启）→ 立刻转 Step 6 换 apex
- 卡开机 → 回滚当前 crDroid 12.12

**第 2 步 · 关键验收项**
- [ ] `adb shell getprop sys.boot_completed` = 1
- [ ] WiFi 能连且**能上网**（BPF 是否修好的唯一判据）
- [ ] 移动数据、VoLTE、短信
- [ ] 相机（弹出前摄需 `GSI-patch-cezanne` 模块）
- [ ] 屏下指纹 —— **大概率不可用**（GSI 架构缺口，非包的问题）
- [ ] 通话音量锁最大、屏幕录制、DT2W 部分失效 —— 已知缺陷，无法绕

**第 3 步 · 稳定性观察**
跑 30 分钟看 `dumpsys dropbox` 有无 system_app_crash / ANR。
