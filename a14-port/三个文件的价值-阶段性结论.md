# 三个文件的价值 —— 阶段性结论

> 2026-11-10 01:15 · 基于字节级分析

## 结论：三个文件都不能直接刷，但把整条技术链摊开了

| 文件 | 直接刷？ | 最大价值 |
|---|---|---|
| `Infinity-X-3.12-GSI_...img` | ❌ A/B 版 + A13 太老 | 唯一纯 GSI 镜像，可作 system 内容参考 |
| `K40G_Android16_..._Fiagelia/` | ❌ MT6893 ≠ MT6889 | **MIO Kitchen 完整工具链**（替代 portingessential） |
| `K40G_OS4.0.5.0_A17.zip` | ❌ 同上 | **A16/A17 移植包 + 4.19/4.14 两套内核** |

## 一、它们解决了什么

### 1. portingessential 阻塞 —— 彻底解除 ✅
K40G 包自带 `bin/cho.exe`（MIO Kitchen 核心）、`zstd.exe`、`fastboot.exe`，
线刷脚本标题就是 `MIO-KITCHEN 刷机助手`。

**SourceForge 全站 Cloudflare 封禁（IP 级，连浏览器都绕不过）已不再是问题。**

### 2. 揭示了一个决定性事实：EROFS 是硬需求 ✅
用官方 `lpdumps`/`lpunpack` 拆开 K40G 的 super.img 后逐个验证：

| 分区 | 格式 | magic |
|---|---|---|
| system_a | **EROFS** | `0xE0F5E1E2` |
| product_a | **EROFS** | `0xE0F5E1E2` |
| system_ext_a | **EROFS** | `0xE0F5E1E2` |
| vendor_a | **EROFS** | `0xE0F5E1E2` |

而 **cezanne 原厂内核 defconfig 里 EROFS/BPF_SYSCALL/MODVERSIONS/FHANDLE 全都没有**
（实测 `grep` 全空）。

→ **原厂内核刷这些包必卡在挂载 system。**

**好消息**：这些镜像 `feature_compat = 0x07`（无 COMPRESS 位）→ **没有压缩**，
所以不需要 `CONFIG_EROFS_FS_ZIP`，省掉整套 LZ4 解压依赖。

### 3. 三个内核的完整 config（从 boot.img 的 IKCFG_ST 段解出）

| | 4.14 Oblivion | 4.19 tiffanyy |
|---|---|---|
| 版本 | `4.14.186-Oblivion-V4.0-DEV-ColorOS` | `4.19.325-cip133-st17-gf8e09661618e` |
| `NET_ACT_BPF` / `BPF_LSM` | ✗ / ✗ | **✓ / ✓** |
| `BPF_SYSCALL` / `NET_CLS_BPF` / `CGROUP_BPF` | ✓ | ✓ |
| `EROFS_FS` | ✓ | ✓ |

→ **A16 用 4.14 即可；A17 必须 4.19**（这解释了包里为什么内核二选一）
→ **Oblivion 的 config 逐条印证我们自编内核的技术路线完全正确**

### 4. 揭示了设备树不可移植 ✅
```
cezanne 原厂 dtbo:  model=CEZANNE   compatible=mediatek,MT6889
K40G A17 dtbo:     model=ARES      compatible=mediatek,MT6893
```
屏/指纹/充电/音频芯片全不同 → **绝对不能刷 K40G 的 dtbo.img**
