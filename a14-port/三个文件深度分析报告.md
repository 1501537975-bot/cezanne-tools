## 二、★★★ 三个决定性发现

### 发现 1：portingessential 阻塞 —— 已彻底解除 ✅

两个 K40G 包自带完整 MIO Kitchen 工具链，**替代 SourceForge 的 portingessential**：

```
bin/cho.exe      1.8 MB   ← MIO Kitchen 核心交互/解包工具
bin/zstd.exe     1.2 MB   ← super.img.zst 解压
bin/fastboot.exe 1.8 MB
bin/right_device       ← 机型校验（防刷错机）
```

`Flash.bat` 标题就是 `MIO-KITCHEN 刷机助手`，流程与 portingessential 一致：
```bat
zstd --rm -d images/super.img.zst -o images/super.img
:: 机型校验, 不匹配就阻止刷入
if not "%DEV_PRODUCT%"=="ares" ( echo 机型不匹配 & exit /b 1 )
```

> **SourceForge 全站 Cloudflare 封禁实测结论**：不是 Turnstile 挑战，而是
> **"Sorry, you have been blocked" 的 IP 级完全封禁** → 浏览器自动化也无法绕过。
> 但我们**已经不需要它了**。

### 发现 2：移植包分区全是 EROFS → 自编内核是必需项 ✅

用官方 `lpdumps` 解析 K40G A16/A17 的 super.img，再 `lpunpack` 拆出分区，逐个验证：

| 分区 | 格式 | magic | feature_compat | 压缩 |
|---|---|---|---|---|
| `system_a` | **EROFS** | `0xE0F5E1E2` | 0x07 | **无** |
| `product_a` | **EROFS** | `0xE0F5E1E2` | 0x07 | **无** |
| `system_ext_a` | **EROFS** | `0xE0F5E1E2` | 0x07 | **无** |
| `vendor_a` | **EROFS** | `0xE0F5E1E2` | 0x07 | **无** |

而 **cezanne 原厂 defconfig 里完全没有 EROFS**（实测 `grep -E "EROFS|BPF_SYSCALL|MODVERSIONS|FHANDLE"` 全空）。

**→ 原厂内核刷这两个包会卡在挂载 system。**

**两个好消息**：
1. `feature_compat = 0x07`（SB_CHKSUM|Mtime|XattrFilter）**无 COMPRESS 位** → 镜像没压缩
   → **不需要 `CONFIG_EROFS_FS_ZIP`**，省掉整套 LZ4 解压依赖
2. mt6873-dev 的 **4.14.336** 树**原生自带 `fs/erofs`** → 与 cezanne 同代码基，冲突比 4.19 移植少得多

### 发现 3：设备树不可移植 —— 只能用 cezanne 原厂 ✅

| 属性 | cezanne 原厂 dtbo | K40G A17 dtbo |
|---|---|---|
| `model` | **`CEZANNE`** | **`ARES`** |
| `compatible` | **`mediatek,MT6889`** | **`mediatek,MT6893`** |
| 屏幕 | `j10_38_08_0a_dsc_cmd,lcm` | K40G 自有 |
| 指纹 | `goodix,gt9896` | `gt9886` / `gt9896s` |
| 充电 | `ti,bq2597x-standalone` | K40G 自有 |
| 音频 | `fsa4480-audioswitch` | `et7480-audioswitch` |

**MT6889 ≠ MT6893** → 刷 K40G 的 dtbo = 屏幕黑、指纹不认、充电不进、相机全废。

## 三、★★★ 三个内核的完整对比（从 boot.img 的 IKCFG_ST 段解出完整 config）

| | **4.14 Oblivion**<br>(`no-root/`) | **4.19 tiffanyy**<br>(`images/`) |
|---|---|---|
| 版本串 | `4.14.186-Oblivion-V4.0-DEV-ColorOS`<br>`(root@localhost) Pdx clang 12.0.0` | `4.19.325-cip133-st17-gf8e09661618e`<br>`(tiffanyy@android-mtk) Android clang 11.0.1` |
| `CONFIG_LOCALVERSION` | `-Oblivion-V4.0-DEV-ColorOS` | `""` + AUTO=y |
| `MODVERSIONS` | ✓ | ✓ |
| `BPF` / `BPF_SYSCALL` | ✓ | ✓ |
| **`NET_ACT_BPF`** | **✗** | **✓** |
| **`BPF_LSM`** | **✗** | **✓** |
| `NET_CLS_BPF` / `CGROUP_BPF` | ✓ | ✓ |
| `EROFS_FS` | ✓ (+ZIP) | ✓ |
| `SYS_CLONE3` / `DEBUG_INFO_BTF` | ✗ | ✗ |

**→ A16 需 4.14 即可；A17 需 4.19**（`NET_ACT_BPF` + `BPF_LSM` 是硬门槛）。
**→ Oblivion 的 config 逐条印证我们自编内核的技术路线完全正确。**

### ★ 但 Oblivion 用不了

它的 vermagic 是 `-Oblivion-V4.0-DEV-ColorOS`，**与原厂 `.ko` 不匹配 → 加载不了原厂 vendor 的 10 个 .ko**。
而移植包的 vendor 是 MT6893 的，也不能用。

**→ 死结 → 必须自编内核**（vermagic 匹配原厂 `4.14.186-perf-00252-g2f26b5917fd6`）。

## 九、踩坑速查

| 坑 | 症状 | 解法 |
|---|---|---|
| `setlocalversion` 双渠道 | 后缀翻倍 | `.config` 留空 + 只走命令行 |
| `set -e` + grep | 静默退出无报错 | 全加 `\|\| true`；用 `scan_sete.py` 扫 |
| **cpio newc** | 解析出乱码名字 | **字段是 ASCII 十六进制**，不是二进制！header=110B |
| **EROFS magic** | 认成 `e2e1f0e3` | 实际是 **`0xE0F5E1E2`**（小端 `e2 e1 f5 e0`） |
| super.img | 找不到 gDla | sparse 首 chunk 是 FILL(4096B)，header 在**逻辑 0x1000** |
| sparse FILL chunk | 整体偏移错位 | FILL 要写 `chunk_sz × blk_sz` 字节 |
| git push | TLS handshake failed | DNS 被劫持到 fake-IP `198.18.0.7`；用 `curloptResolve` |
| mt6873 仓库 | raw 404 | 分支是 **`cgroup-v2`**，不是 main |
| bash 吞字符 | 命令跑飞 | 路径里的 `-` 会被吞 → 改用文件方式写脚本 |
